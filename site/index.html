GDC MCP 플러그인

사용 안내서

Claude Code와 Claude Desktop에서 GDC 태스크를 조회·생성·수정하고, 작업 요청 문서와 연결해 진행률을 동기화하는 MCP 플러그인입니다. 설치부터 일상적인 사용까지 순서대로 담았습니다.

사용하는 앱을 먼저 고르세요. 설치 절차·명령·화면 등 안내 전체가 선택한 환경에 맞춰 바뀝니다.

1 설치 및 설정 · 1-2 플러그인 설치

플러그인 설치

Claude Code 안에서 마켓플레이스를 등록한 뒤 설치합니다. 설치 정보는 각 PC의 Claude Code 설정(~/.claude)에 저장되므로 PC마다 1회 수행합니다.

  1. 1

    대화창에 마켓플레이스를 등록합니다. /plugin marketplace add seonmikii/gdc-claude-plugin

  2. 2

    이어서 플러그인을 설치합니다. /plugin install gdc-claude-plugin@gdc-marketplace

  3. 3

    /reload-plugins 를 실행하거나 Claude Code를 다시 시작합니다.

여러 명이 공용 GDC 계정을 쓰더라도 플러그인 설치는 각 PC에서 따로 해야 합니다. 이미 설치한 뒤 새 버전을 받으려면 /gdc-update 를 실행하고 Claude Code를 재시작합니다. 설치가 EBUSY 로 실패하는 경우는 「05 자주 묻는 문제」에 있습니다.

MCP 서버 등록

레포를 클론하고 Claude 데스크탑 앱의 설정에 서버를 추가한 뒤 앱을 재시작합니다. PC마다 1회 수행합니다.

  1. 1

    레포를 클론합니다.git clone https://github.com/seonmikii/gdc-claude-plugin

  2. 2

    Claude 데스크탑 앱의 설정을 엽니다.

  3. 3

    왼쪽 「Developer」 탭에서 「Edit Config」 를 누릅니다. 설정 파일이 없으면 새로 만들어 열어 주므로 경로를 직접 찾을 필요가 없습니다.

    Windows %APPDATA%\Claude\claude_desktop_config.json
    macOS ~/Library/Application Support/Claude/claude_desktop_config.json
    파일을 직접 열어도 됩니다. 경로는 OS마다 다르니 해당하는 줄만 복사하세요.
  4. 4

    열린 파일에 오른쪽 내용을 넣고 <클론 경로> 를 실제로 클론한 폴더 경로로 바꿉니다.

  5. 5

    Claude 데스크탑 앱을 완전히 종료했다가 다시 엽니다. 창만 닫아서는 반영되지 않습니다.

메뉴 이름은 공식 MCP 안내를 따랐습니다. Connect to local MCP servers ↗
새 버전을 받으려면 클론한 폴더에서 git pull 하고 앱을 재시작합니다. Claude 데스크탑 앱에는 플러그인 개념이 없어 /gdc-update 에 해당하는 기능이 없습니다.

2 작업 흐름 · 2-2 내 태스크 조회

내 태스크 조회

현재 프로젝트에서 본인이 담당·작성·참여 중인 미해결 태스크를 마감일 순으로 조회합니다.

  1. 1

    /gdc-my-tasks 를 입력합니다. 내가 담당자·작성자·관련자 중 하나이면서 아직 끝나지 않은 태스크를 예상 종료일이 빠른 순으로 최대 20건 조회합니다.

    gdc_my_tasks 프롬프트를 실행합니다. 내가 담당자·작성자·관련자 중 하나이면서 아직 끝나지 않은 태스크를 예상 종료일이 빠른 순으로 최대 20건 조회합니다.

    “내 태스크 보여줘”
  2. 2

    범위를 좁히려면 옵션을 붙입니다.

    # 마감 지난 것만 /gdc-my-tasks --overdue # 날짜 미정 /gdc-my-tasks --undated # 완료 포함 전부 /gdc-my-tasks --all

    범위를 좁히려면 말로 덧붙이면 됩니다 — “마감 지난 것만”, “날짜 미정인 것”, “완료된 것도 포함해서”.

  3. 3

    다른 사용자의 태스크는 /gdc-tasks <이름> 으로 조회합니다.

작업 요청 문서로 일하기

작업 요청 문서와 태스크를 연결하여, 작업의 진행 상황과 내용에 맞게 GDC의 태스크를 간편하게 업데이트합니다.

아래 세 단계는 하나의 흐름입니다. 문서와 태스크를 한 번 짝지어두면, 그 뒤로는 체크박스를 채우는 것만으로 태스크 진행률이 움직이고, 작업하며 달라진 내용이 태스크로 돌아갑니다.

2 작업 흐름 · 2-4 진행률 동기화

진행률 동기화

2-3에서 연결해두면 따라오는 결과입니다. 문서의 단계별 체크박스를 채우면 연결된 태스크의 진행률과 상태가 알아서 갱신됩니다.

  1. 1

    문서 「수행 계획」의 단계를 완료할 때마다 체크합니다.

  2. 2

공통 입력 규칙

담당자·관련자는 user id 대신 이름으로 입력할 수 있습니다. 자동으로 계정을 해석하며, 프로젝트 멤버가 아니면 처리하지 않고 후보 목록을 안내합니다. 날짜는 YYYY-MM-DD 형식이며 시작일이 종료일보다 늦거나 실제 종료일이 미래인 경우 차단됩니다. 본문·댓글에 입력한 주소와 #번호는 자동으로 링크 처리됩니다.

자주 묻는 문제

막혔을 때 먼저 확인할 것들입니다.

설치가 EBUSY: resource busy or locked 로 실패하는 경우

실행 중인 MCP 서버가 캐시 폴더를 점유한 상태입니다.

플러그인을 Disable 후 재설치하거나, Claude Code를 완전히 종료한 뒤 재시작하고 다시 실행합니다.

gdc-local이 Connected로 표시되지 않는 경우

먼저 uv --version 이 정상 동작하는지 확인합니다. MCP 서버를 uv 로 기동하므로 uv가 없으면 연결되지 않습니다.

uv가 정상인데도 연결되지 않으면 /reload-plugins 를 실행하고, 그래도 해결되지 않으면 Claude Code를 완전히 재시작합니다.

gdc_* 프롬프트가 "+" 메뉴에 보이지 않는 경우

거의 항상 설정 파일 문제입니다. claude_desktop_config.json 이 올바른 JSON인지 확인하세요. 마지막 쉼표 하나, Windows 경로의 이스케이프되지 않은 역슬래시 하나로도 Claude Desktop이 파일 전체를 조용히 무시합니다.

그리고 uv --version 이 동작하는지, --directory 경로가 실제 클론한 폴더를 가리키는지 확인합니다. 고칠 때마다 Claude Desktop을 재시작해야 반영됩니다.

로컬 문서를 못 읽는 경우

Claude Desktop에는 작업 중인 레포라는 개념이 없어서, 문서 연동 기능(2-3~2-5)은 파일 접근 설정에 따라 달라지고 아예 안 될 수도 있습니다.

작업 요청 문서로 일한다면 그 단계는 Claude Code에서 하시는 편이 낫습니다. 나머지 기능은 양쪽이 동일합니다.

「프로젝트가 설정되지 않았습니다」 오류가 나오는 경우

현재 폴더에 워크스페이스·프로젝트 컨텍스트가 지정되지 않은 상태입니다. 컨텍스트는 폴더 단위로 저장되므로 새 레포에서는 다시 지정해야 합니다.

인증 전이면 /gdc-login, 이미 인증된 상태면 /gdc-switch 로 프로젝트만 변경합니다.

워크스페이스·프로젝트가 선택되지 않은 상태입니다. 인증 전이면 gdc_login 프롬프트를, 이미 인증된 상태면 gdc_switch 프롬프트로 프로젝트만 변경합니다.

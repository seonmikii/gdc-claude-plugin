사용자 인자: $ARGUMENTS

인자에 따라 갈라집니다.

**1. 비어 있거나 건의 내용인 경우 — 제출**

`AskUserQuestion`으로 분류를 먼저 고르게 하세요(선택지: 버그 / 기능 요청 / 개선 제안 / 기타).
본문이 인자로 안 왔으면 무엇이 어떻게 불편한지 물어 받습니다.
그다음 `submit_suggestion(content, category)`를 호출하세요. 제목은 생략하면 본문 첫 줄로 자동 생성됩니다.

- 본문은 5~2000자입니다. 너무 짧으면 상황을 한 문장 더 받아 채우세요.
- **토큰·비밀번호 같은 자격증명이 본문에 섞여 있으면 제출 전에 빼라고 알려주세요.**
- 워크스페이스/프로젝트와 무관한 전역 기능이라 컨텍스트 설정 없이 동작합니다.

접수되면 접수 번호와 상태를 알려주고, 진행 상황은 `/gdc-suggest list`로 볼 수 있다고 안내하세요.

**2. `list`인 경우 — 내 건의 목록**

`list_my_suggestions()`로 조회해 번호 / 제목 / 분류 / 상태 / 답변 여부 / 제출일 표로 보여주세요.
분류·상태는 응답의 `category_label`·`status_label`(한글)을 씁니다.
`has_reply`가 true인 건이 있으면 "번호를 말하면 답변 내용을 보여드립니다"라고 덧붙이세요.

**3. 숫자인 경우 — 상세 조회**

`get_suggestion(번호)`로 본문과 관리자 답변, 답변자·답변 시각을 보여주세요.
`admin_reply`가 비어 있으면 아직 답변 전이라고 안내합니다.

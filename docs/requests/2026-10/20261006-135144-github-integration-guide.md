## 요청 내용

GDC의 GitHub 연동 방법을 **현재 운영 배포(https://gdc.gemiso.com) 기준**으로 정리해 안내서 페이지 하나로 만든다.

진행 중 추가 지시:
- 캡처 누락 지적 → 사용자가 별도 Chrome 창(작업 전용 프로필)에서 직접 로그인하고, 이후 이동·캡처는 원격 제어로 진행.

## 배경

- 지금은 매뉴얼 '프로젝트 → 연동'에 GitHub 연동이 한 줄로만 소개되어 있고(제머나이소프트 `gemiso-dev` 조직 레포만 연결 가능, 설정 → 연동에서 계정 연결 시 담당자·작성자 자동 매핑), 설치부터 사용까지 순서대로 안내하는 문서가 없다.
- 이 레포에 남은 근거(20260828-110334-mcp-task-pr-link): 레포 연결은 `해제 안 됨 ∧ 동기화 켜짐 ∧ GitHub App 설치 활성`일 때만 쓸 수 있고, PR 연결 출처는 수동(`manual`)·PR 본문 자동(`auto`)·이슈 참조 키워드 자동(`auto_issue`) 3종이며, PR 후보 조회에는 GitHub App의 `Pull requests: Read-only` 권한이 필요하다.

## 수행 계획

1. 운영 기준 확인 — gdc-service `origin/develop`(운영과 일치) 코드와 운영 화면으로 아래 흐름의 실제 동작·조건·권한을 확인한다. (gdc-service는 읽기만 한다)
2. 새 페이지 `site/github.html` 작성 — 웹훅 안내서(`site/webhook.html`)와 같은 디자인·목차·한/영 전환 구조. 예상 목차:

```
GitHub 연동 안내서
 01 워크스페이스에 GitHub 설치 연결   (워크스페이스 설정 → 기타, 관리자)
 02 프로젝트에 레포지토리 연결         (프로젝트 → 연동 탭)
 03 내 GitHub 계정 연결               (설정 → 연동, 담당자·작성자 자동 매핑)
 04 태스크에서 사용하기               (GitHub 이슈 발행 · PR 연결 · PR 본문 자동 연결)
 05 자주 묻는 문제
 06 더 알아보기                       (매뉴얼 · MCP 안내서 · 웹훅 안내서)
```

3. 캡처 — 운영 화면에서 찍고 실명·이메일·토큰 등은 흐림 처리한다(기존 매뉴얼 캡처 규칙과 동일).
4. 다른 안내서와 연결 — 매뉴얼 '프로젝트 → 연동'의 GitHub 문장, 세 안내서의 '더 알아보기'에 새 페이지를 추가한다.
5. 검증 — 목차 앵커·이미지 로드·링크 주소, 헤드리스 렌더링(한/영).

## 참고 사항

- MCP 도구/서버 동작을 바꾸지 않는 문서 작업이라 로컬 사전 검증은 생략한다.
- 페이지 골격(스타일·한/영 전환·목차 스크롤·이미지 확대 스크립트)은 `site/webhook.html`과 같은 것을 쓴다.
- 코드로 확인한 매뉴얼 기존 설명과의 차이: ① 'gemiso-dev 조직 레포만'은 GDC 코드가 아니라 GitHub 앱 설치 범위에서 오는 제한이다(앱 설정 자체는 미확인, 안내서에는 "앱이 설치·허용된 레포만, 현재 gemiso-dev"로 기술) ② GDC → GitHub 반영은 이슈별 스위치이며 가져온 이슈는 꺼진 상태로 시작한다 ③ 새 레포를 고르려면 프로젝트 관리자라도 워크스페이스 소유자·관리자 권한이 필요하다. 매뉴얼 본문은 링크 추가 외에 고치지 않았다.
- 캡처하며 바로잡은 표기: 「전체 가져오기」는 ⋯ 메뉴가 아니라 「변경분 가져오기」 옆 ▾ 안에 있음(동기화 일시중지·연동 해제가 ⋯ 메뉴), 워크스페이스 설정은 왼쪽 위 워크스페이스 이름 메뉴에서 진입, 개인 설정은 사이드바 맨 아래 「설정」.
- gdc-service 쪽 참고(본체 미수정): 프로젝트 생성 화면 안내 문구 "추후 프로젝트 설정에서 추가할 수 있습니다"는 실제로는 '연동' 탭이다. 설계 문서 20260904-125710의 카드 제목 변경("GitHub 앱 설치")은 코드에 반영되어 있지 않다.

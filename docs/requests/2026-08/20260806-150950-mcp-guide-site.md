## 요청 내용

GDC 공지사항에 MCP 플러그인 사용 안내를 올린다. 어떤 기능이 있는지 간략히 소개하고, 작업 워크플로우에 맞춘 사용 예시를 보여준다. 사용자가 제시한 시나리오는 다음과 같다.

1. **할 일 정리** — 태스크 생성 / 태스크 조회
2. **작업 선택** — 태스크 기반 작업 요청 문서 생성 / (hotfix) 작업 요청 문서로 태스크 생성 / 진행률 자동 동기화
3. **작업 마무리** — `/gdc-apply`

## 배경

### 처음 검토한 방향과 그 폐기 사유

공지 본문 안에 안내서를 담는 3가지 방안(평문 유지 / TipTap 리치텍스트 전환 / 이미지 첨부)을 비교 미리보기로 제시했으나, **셋 다 "공지 본문에 안내서를 통째로 넣는다"는 동일한 전제 위의 변주**였고 사용자가 이를 기각했다. 공지는 알림이고 안내서는 문서라 매체를 분리하는 것이 맞다.

**별건으로 발견 — 공지 다이얼로그에 스크롤이 없다.** `dialog.tsx:62`의 `DialogContent`는 `fixed top-[50%] translate-y-[-50%]`로 중앙 고정인데 `max-height`도 `overflow-y`도 없다. 공지 상세는 `max-w-lg`(512px). 긴 공지는 화면 밖으로 잘려 아래쪽을 읽을 방법이 없다. 이번 작업은 공지를 7줄로 줄여 이 문제를 우회하므로 **수정하지 않는다.** gdc-service 쪽 별건으로 남긴다.

**별건으로 발견 — `docs/requests` 24건이 public 레포에 공개돼 있다.** 내부 서버 주소(`se.gemiso.com:11521`), 워크스페이스·태스크 번호, 검증 절차가 포함된다. 의도된 상태인지 확인이 필요하다. 이번 작업 범위 밖이라 손대지 않는다.

### 배포처 결정

사용자가 **GitHub Pages**를 선택했다. 레포가 PUBLIC이라 무료로 쓸 수 있고, 설치 안내가 이미 이 레포를 가리키고 있어 팀원이 이미 접근한다. 갱신이 커밋으로 끝나므로 플러그인 버전 상향과 같은 PR에서 문서가 함께 갱신된다.

**`docs/`를 Pages 소스로 잡지 않는다.** 작업 요청 문서 24건과 `INDEX.md` 작업 이력이 사이트로 색인되면 안 된다. `site/`만 배포한다.

### 반영 중 잡은 결함 3건

- **환경 탭이 일부 블록에 먹지 않았다.** 숨김 규칙 `.e-code, .e-desktop { display: none }`(명시도 0-1-0)이 뒤에 오는 `.steps{flex}` `.screen{flex}` `.qa{grid}`(같은 명시도, 나중 선언 우선)에 밀려 Desktop 전용 블록 5개가 Code 탭에서도 보였다. `display`를 다시 부여하는 방식(`revert`)은 UA 기본값으로 되돌아가 `flex`/`grid` 레이아웃을 깨뜨리므로, **숨기기 전용 규칙 + `!important`** 로 바꿨다 — 보여줄 때는 아무 값도 건드리지 않으니 각 요소가 자기 `display`를 그대로 유지한다.
- **언어 전환이 타이핑 데모의 원문을 파괴했다.** 데모는 재생 중 요소를 비우고 원문을 `data-full`에 캐시하는데, 언어 전환이 그 캐시를 지우고 재생을 시켰다. 재생 시점의 텍스트는 비었거나 타이핑 중이라 그 빈 문자열이 새 "원문"으로 굳어 줄이 영구히 사라졌다. 캐시를 지우는 대신 **교체 직후의 텍스트로 갱신**하도록 바꿨다(`data-en`이 없는 줄은 언어와 무관하므로 손대지 않는다).
- **Desktop 탭에서 목차의 1-2 링크가 죽었다.** `#b12`가 Code 전용 섹션에 붙어 있어 Desktop에서는 숨겨진 요소를 가리켰다. 두 변형을 `#b12` 래퍼로 감싸 어느 환경에서든 보이는 쪽에 안착한다.

#### 2-5 캡처 교체

`gdc.gemiso.com/tasks/15576`(#437 삭제·휴지통 아이콘 색상 변경)은 세 가지 옵션이 한 화면에 다 있어 예시로 적합하다 — 본문 「작업 내용」 블렛, 계획이 바뀐 이유를 적은 댓글(참조 문서 경로 포함), 우측 변경 이력의 수정 전후 비교.

**운영 화면이라 사이드바를 제외하고 촬영했다.** 좌측 프로젝트 목록에 고객사명 13건(POSCO·삼성서울병원·경찰청 등)이 그대로 떠 있었고, 이 사이트는 PUBLIC Pages 배포다. 「시각 자료 체계」에 기록해 둔 대응(필요한 영역만 잘라낸다)을 그대로 적용해 `aside`를 숨기고 본문 영역만 담았다. 남는 노출은 태스크 제목·상위 태스크명(GDC 자체 로드맵)과 담당자·작성자 이름(레포 소유자 본인)뿐이다.

**작아서 안 읽히는 문제는 레이아웃이 아니라 클릭 확대로 풀었다.** 새 캡처는 3분할이라 우측 컬럼(약 460px)에서는 글자를 읽을 수 없다. 처음에는 이 블록만 전체 폭으로 폈으나 2-5만 다른 리듬이 되어 되돌렸고, 대신 **모든 실캡처를 클릭하면 크게 열리도록** 했다. 캡션(「세 가지 옵션이 한 화면에…」)도 사용자 요청으로 삭제했다.

클릭 확대는 `position: fixed`가 아니라 **absolute + 클릭한 썸네일 기준 배치**다. 이 페이지는 자체 스크롤이 없는 자동 높이 프레임(아티팩트) 안에서도 렌더되는데, 거기서 `fixed`는 보이는 영역이 아니라 문서 전체의 최상단에 붙어버린다. 방금 클릭한 썸네일의 중심에 맞춰 띄우면 어느 쪽에서든 화면 안에 들어온다. 닫기는 배경 클릭·`Esc`·닫기 버튼 세 가지고, 이미지에 `tabindex`·`role=button`을 줘 키보드로도 열린다. 인쇄 시에는 숨긴다.

**촬영 중 확인 — 화면 전체는 쓸 수 없는 경우가 있다.** GDC 사이드바에는 브라우저에 선택된 워크스페이스의 프로젝트 목록이 항상 뜬다. 운영 워크스페이스가 선택돼 있으면 고객사명이 그대로 노출되므로, 촬영 전 워크스페이스를 전환하거나 필요한 영역만 요소 단위로 잘라낸다. 촬영 후에는 브라우저 워크스페이스를 운영으로 되돌린다.

**GIF를 쓰지 않는다.** 대신 타이핑 애니메이션으로 대화 진행을 표현한다. 용량이 거의 들지 않고 문구 수정이 자유로우며, 플러그인 UI가 바뀌어도 재녹화가 필요 없다.

**타이핑은 CSS가 아니라 JS로 구현했다.** CSS `steps()` 방식은 `width`를 `ch` 단위로 잡는데, 한글 글자 폭은 `ch`의 정수배가 아니라 제목 줄에서 어긋난다. 글자를 하나씩 넣는 JS 방식이 폰트와 무관하게 정확하다.

좁은 화면에서는 좌/우가 위/아래로 접힌다. 커맨드 블록은 클릭하면 복사되며, `#` 주석 줄은 복사에서 제외된다.

**우측 화면의 강조 표시는 제거했다.** 초기에는 좌측 콜아웃 번호와 화면 속 빨간 라운드 박스를 1:1 대응시켰으나, 사용자 요청으로 전부 걷어냈다. 선택 단계는 알약이 눌리는 애니메이션만으로 표현한다.

### 애니메이션 규칙

- 뷰포트 진입 시 **1회만** 재생, 「다시 보기」 버튼 제공
- `prefers-reduced-motion: reduce` → 애니메이션 없이 최종 상태 즉시 표시
- 인쇄(`@media print`) 시 최종 상태로 고정

### 파일 구조

**이미지는 `data:` URI로 본문에 인라인한다.** `assets/` 폴더와 `SHOTLIST.md`는 만들지 않는다. 단일 파일이라 배포·이동이 단순하고, 아티팩트 미리보기(외부 리소스 차단)에서도 그대로 보인다. 대신 파일이 커진다(캡처 3장 포함 약 550KB).

**정본은 `site/index.html` 하나다.** 초기안의 `guide-src.html` + `shots/` 토큰 치환 방식은 쓰지 않는다 — 편집 대상이 둘로 갈리면 어느 쪽이 최신인지 흐려진다. `site/index.html`은 doctype·`head`·`body`를 갖춘 표준 문서라 Pages가 그대로 서빙할 수 있다.

아티팩트 게시본만 파생물이다. 아티팩트는 게시 시점에 자체 `head` 골격을 씌우므로 그 태그들이 있으면 안 되는데, `build-artifact.py`가 `<title>`·`<style>`·`body` 내용만 뽑아 `artifact.html`을 만들고 골격 태그가 새어 들어가지 않았는지 검사한다.

```
site/index.html         정본 — 표준 HTML 문서, 이미지는 data: URI 인라인 (약 620KB)
site/build-artifact.py  index.html → artifact.html 변환 (uv run python site/build-artifact.py)
site/artifact.html      아티팩트 게시용 파생물 — 골격 태그 제거본
```

`artifact.html`은 매번 재생성되는 파생물이라 커밋할 필요가 없다. `site/.gitignore`로 제외할지는 5단계에서 정한다.

### 리스크

- GDC 실캡처는 로그인된 Chrome 세션을 chrome-devtools로 제어할 수 있어야 한다. 작업 중 `The browser is already running for …chrome-profile` 로 두 차례 막혔고, 사용자가 해당 창을 닫아야 재연결됐다.
- 단일 파일 인라인 방식이라 캡처를 추가할수록 파일이 선형으로 커진다. 지금은 문제없지만 캡처가 10장을 넘어가면 `assets/` 분리를 다시 검토한다.

## 요청 내용

설명(description)이나 댓글에 URL·태스크 언급을 평문으로 넣으면 현재는 클릭 가능한 링크로 연동되지 않는다. 평문 → GDC 리치텍스트(HTML) 변환 시 다음을 자동 연동한다.

- **URL 자동 연동**: 평문에 포함된 `http`/`https` URL을 `<a href>` 링크로 변환.
- **태스크 언급 자동 연동**: 태스크를 언급하면(`#번호` 등) 해당 태스크 상세 페이지 링크로 변환.

두 요구 모두 description·댓글 **양쪽**에 적용되어야 한다(태스크 원문 AS-IS가 "설명이나 댓글" 명시).

## 배경

### 현황 (관련 코드 검토)

- 평문 → HTML 변환은 [doc_utils.py:49](gdc_mcp/doc_utils.py#L49) `description_to_html`가 단일 진입점이다. 텍스트를 `html.escape`로 이스케이프만 하고 URL/태스크 언급을 링크로 만들지 않는다(블렛·라벨·일반 줄 3곳에서 escape 수행).
- 이 함수는 `normalize_description`([doc_utils.py:44](gdc_mcp/doc_utils.py#L44)) → **description 경로**(create_task/update_task)와, `_build_comment_html`([server.py:1296](gdc_mcp/server.py#L1296)) → **댓글 경로**가 **공유**한다. 따라서 URL 자동 연동은 이 한 함수에 구현하면 양쪽에 동시에 적용된다.
- GDC 리치텍스트는 링크를 지원한다(실증: 태스크 #292 저장 description에 `<a target="_blank" rel="noopener noreferrer" href="...">` 존재).
- 태스크 상세 URL은 내부 **id** 기준이다(`_task_url` = `{_WEB_URL}/tasks/{id}`, [server.py:48](gdc_mcp/server.py#L48)).

### 결정 사항 (확정)

1. **태스크 언급 문법** — **권장안 채택**: URL 자동 연동을 공통 함수로 **먼저 구현**하고, 번호(`#N`) 기반 태스크 언급 연동은 (A) 서버 계층(번호→id REST 조회)으로 **후속 처리**(문법·비용 별도 확인). 이번 범위는 URL 자동 연동에 한정한다.
2. **URL 인식 범위** — **맨 URL만**: `http`/`https` 스킴 URL만 대상. 이메일·상대경로·`www.`는 제외(오탐 방지).

## 후속 작업: 태스크 언급(`#N`) 연동 — 완료

> **완료 2026-07-28, v0.6.1** → 별도 문서 [20260728-102213-task-mention-autolink.md](20260728-102213-task-mention-autolink.md)에서 구현·검증.

결정 1(권장안)대로 URL 자동 연동에 이어 후속 분리했던 항목. 확정·구현 요약:

- **언급 문법**: `#N`, 경계 `(?<![\w#])#(\d+)\b` — 색상 `#fff`·단어 뒤 `v1#2`·마크다운 헤더 `# 제목` 제외, URL 내부 프래그먼트(`...#409`)는 URL 구간 선소비로 미처리.
- **표시 텍스트**: `#N`만 링크 + 바로 뒤 `(제목)` 평문 삽입.
- **미해결 번호**: 평문 유지. **스코프**: 현재 컨텍스트 프로젝트 번호만.
- **구현**: `_escape_and_linkify`에 `resolve_task` 콜백 추가(순수 로직, 미주입 시 하위 호환), 서버 `_task_resolver`가 번호→(url, title) 매핑. gdc-service에 번호 필터가 없어(`TaskFilter`·BM25 실증) `-number` 목록을 페이지 스캔한다. description·댓글 5개 경로 연결. 상세·비용·검증은 후속 문서 참조.
